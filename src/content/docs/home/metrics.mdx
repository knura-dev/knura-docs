knurd can serve a `/metrics` page that Prometheus reads, so you can chart it in Grafana and get alerts when something goes wrong. It's off until you turn it on. Logs tell you what happened to one tap. Metrics tell you how knurd is doing over time.

:::note[Newer than v0.6.1]
The metrics page arrives in the next release after v0.6.1. If knurd ignores `metrics.port`, update it from the [latest release](https://github.com/knura-dev/knura/releases).
:::

:::tip[Using a hosted account?]
There's nothing to set up. We watch the hosted service for you.
:::

## Turn it on

<Steps>

1. Add a port to `knurd.properties` in your settings folder:

   ```properties
   metrics.port=9425
   ```

2. Restart knurd. Its log says `Prometheus metrics on http://127.0.0.1:9425/metrics`.

3. Check that it answers:

   ```sh
   curl http://127.0.0.1:9425/metrics
   ```

</Steps>

### Prometheus on another computer

By default the page only answers this computer. If Prometheus runs somewhere else on your network, also set this computer's LAN or Tailscale address (or `0.0.0.0` in a container):

```properties
metrics.listen.host=192.168.1.20
```

## Is it safe?

The page has no login, which is what Prometheus expects. It holds no secrets and nothing about any one tag: no tag IDs, tag names, connection names or addresses, only totals.

Keep it off the internet anyway. knurd only listens on this computer or a home network address, only answers callers from those networks, and refuses requests that came through a proxy or tunnel. Don't point Tailscale Funnel or a router port forward at it.

## Point Prometheus at it

Add knurd to `prometheus.yml`:

```yaml
scrape_configs:
  - job_name: knurd
    static_configs:
      - targets: ["192.168.1.20:9425"]
```

## What it shows

### Taps and actions

| Metric | What it means |
| --- | --- |
| `knurd_taps_total{result}` | Taps checked. `result` is `ok`, `malformed`, `rejected` (a forged link or a tag knurd has no key for), `replay` (a copied link), `error` (knurd failed while checking) or `throttled` (too many failed taps from one address). |
| `knurd_tap_verify_seconds` | How long checking a tap took, as a histogram. |
| `knurd_actions_started_total` | Actions started by genuine taps. |
| `knurd_actions_total{outcome}` | How actions ended: `delivered`, `refused` (the other end said no) or `expired` (no answer after retrying). Tests from the dashboard aren't counted. |
| `knurd_tags_with_actions` | Tags that have actions set up. |

### Java health

knurd runs on Java, so these show whether it has enough memory and isn't stuck.

| Metric | What it means |
| --- | --- |
| `jvm_memory_used_bytes{area}` | Memory in use. `heap` is knurd's data, `nonheap` is its code. |
| `jvm_memory_committed_bytes`, `jvm_memory_max_bytes` | Memory reserved from the system, and the limit (`-1` means none). |
| `jvm_threads_current`, `jvm_threads_daemon`, `jvm_threads_peak` | Threads alive now, and the most at once. knurd answers requests on lightweight virtual threads, which aren't counted. |
| `jvm_gc_collections_total{gc}`, `jvm_gc_collection_seconds_total{gc}` | Garbage collections, and the time they took. |
| `jvm_classes_loaded`, `jvm_info` | Loaded classes, and which Java runs knurd. |
| `process_uptime_seconds`, `process_start_time_seconds` | How long knurd has been running. If it drops back to zero, knurd restarted. |
| `process_cpu_seconds_total`, `process_available_processors` | CPU time used, and the cores Java may use. |
| `process_open_fds`, `process_max_fds` | Open files and connections, and the limit. Linux and macOS only. |

## Useful queries

```promql
# Taps per minute, by result
sum by (result) (rate(knurd_taps_total[5m])) * 60

# Forged or copied links in the last hour
increase(knurd_taps_total{result=~"rejected|replay"}[1h])

# The slowest 5% of tap checks, in seconds
histogram_quantile(0.95, sum by (le) (rate(knurd_tap_verify_seconds_bucket[5m])))

# Share of actions that didn't arrive
sum(rate(knurd_actions_total{outcome!="delivered"}[15m])) / sum(rate(knurd_actions_total[15m]))

# Heap in use, as a share of the limit
jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"}
```

## Alerts worth having

| Alert | Rule |
| --- | --- |
| knurd is down | `up{job="knurd"} == 0` for 5 minutes |
| An action never arrived | `increase(knurd_actions_total{outcome="expired"}[15m]) > 0` |
| Someone is trying old or fake links | `increase(knurd_taps_total{result=~"rejected\|replay"}[1h]) > 10` |
| Running out of memory | heap share above `0.9` for 10 minutes |
| Running out of files | `process_open_fds / process_max_fds > 0.8` |
